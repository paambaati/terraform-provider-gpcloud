# tf-workspace

A self-contained Terraform workspace for testing the `paambaati/gpcloud` provider end-to-end against the [Terraform Registry](https://registry.terraform.io/providers/paambaati/gpcloud).

This workspace is used by the [terrably E2E CI workflow](../.github/workflows/e2e-terrably-upgrade.yml) to verify that every published provider version actually runs `terraform plan`, `apply`, and `destroy` correctly.

---

## Contents

| File | Description |
|------|-------------|
| `main.tf` | Root module — provider config, `gpcloud_item` resource, and `item_id` output |
| `versions_override.tf` | _(generated by CI)_ Pins an exact provider version for testing; not checked-in |

---

## Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/downloads) ≥ 1.0 or [OpenTofu](https://opentofu.org) ≥ 1.6
- A running GPCloud API (or the stub at `http://127.0.0.1:8765` started by the provider's API server)

---

## Quickstart (registry version)

```bash
terraform init
terraform plan
terraform apply
terraform destroy
```

`terraform init` downloads the latest stable `paambaati/gpcloud` release from the Terraform Registry automatically.

---

## Pinning a specific version

To test a specific release, create a `versions_override.tf` file (this is what CI does) –

```hcl
# tf-workspace/versions_override.tf  — do NOT commit
terraform {
  required_providers {
    gpcloud = {
      source  = "paambaati/gpcloud"
      version = "= 0.0.20"
    }
  }
}
```

Then run `terraform init -upgrade` to switch to that exact version.

## Local development (dev overrides)

To use a binary you built locally instead of pulling from the registry:

1. Create `.terraformrc` in this directory:

```hcl
provider_installation {
  dev_overrides {
    "paambaati/gpcloud" = "/absolute/path/to/terraform-provider-gpcloud/bin"
  }
  direct {}
}
```

2. Point Terraform at it before running any command:

```bash
export TF_CLI_CONFIG_FILE="$(pwd)/.terraformrc"
terraform plan   # no init needed with dev_overrides
```

The CI workflow removes `.terraformrc` before running `terraform init` so that the registry version is always used in E2E tests.

## Configuration

The workspace uses these provider settings:

```hcl
provider "gpcloud" {
  api_url = "http://127.0.0.1:8765"
}
```

Override `api_url` via a `terraform.tfvars` file or `TF_VAR_*` environment variables if you're pointing at a real API endpoint.
